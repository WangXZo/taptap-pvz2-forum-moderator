# 答疑库 · 条目模板（2026-11-25 起：一条一文件）

> 新条目写到 **`qa/entries/<id>.md`**（一条一个文件）。
> 也可以一条命令提交，自动过质量闸 + 拆要点 + 合并：
>
> ```bash
> node scripts/qa-admin.mjs submit --question "…" --answer-file 答案.md
> ```
>
> 改完**不用改代码**，下一轮自动生效。

## 文件格式

```markdown
---
id: q-tahuang-wujin-dapei
question: 买了塔黄无尽用什么好
keywords: [塔黄, 保龄球, 卡波, 塔黄无尽]
version: 通用
confidence: 70
updated: 2026-11-26
source: https://www.taptap.cn/moment/863832282933232344
---

## 要点
- [70%] 优先买神器保龄球
  - 来源: https://www.taptap.cn/moment/863832282933232344
- [50%] 卡波建议塔黄空吸到最高再点下一波
  - 来源: https://www.taptap.cn/moment/863999999999999999
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 稳定身份，**写入后不要改**（改了会被当成新条目）。`q-` + 问法 slug，同问法恒得同 id |
| `question` | ✅ | 标准问法（一行）。改问法可以，id 不变就行 |
| `keywords` | ✅ | 玩家在帖子里**真实会用的词**，逗号分隔。这是打分主依据，比问法本身更重要 |
| `version` | 否 | 仅备注，默认「通用」 |
| `confidence` | 否 | 条目整体置信度百分比。不写则按要点最高值；无来源的人工条目默认 95 |
| `updated` | 否 | 最后更新日期 |
| `source` | 否 | 来源链接（**可追溯性，不是隐私**，鼓励保留） |
| `author` / `signature` | 否 | 摘自哪位玩家（会给昵称遮罩处理） |
| `semanticConfirm` | 否 | `true` = 命中后需 LLM 语义确认才用（防笼统套用） |

### 要点（claim）—— 核心

一个答案 = **多个可独立评价的具体点**，每点带自己的置信度与来源。

| 要求 | 说明 |
|---|---|
| 一个要点 = 一个可独立评价的说法 | 没法单独判断对错的就不算要点 |
| 不拆成词/短语 | 「保龄球」「塔黄」是词，不是要点 |
| 也别把两件无关的事塞一起 | 一条只讲一件事 |
| 数字/名称/机制**原样保留** | 那是事实核验的对象，改写就失真 |
| 一段答案 1~6 条 | 本来就一句话就只给 1 条 |

**置信度口径**（社区沉淀最高只到「高」，可信档只给官方资料与人工确认）：

| 情况 | 置信度 |
|---|---|
| 官方来源 / 人工核实 | 95 |
| >3 个独立渠道且 ≥3 个玩家说法一致 | 80 |
| ≥2 个独立渠道一致 | 70 |
| 单一社区来源 | 50 |
| 有未解决的反对票 | 30 |

**重要**：新答案**不会覆盖**已有高置信度要点 —— 同义就并来源重算置信度，异义就作为补充要点并列，矛盾会标出来等人复核。

## 旧形态（兼容期）

`qa/答疑库.md` 单文件形态**仍然能读**（`qa/entries/` 为空时回退读它），
但**新内容一律写 entries/**。旧格式是这样（供参考，别再用）：

```markdown
## 问：钻石怎么快速获得
- 关键词：钻石, 刷钻, 免费钻石
- 版本：通用
---
钻石主要靠这几个稳定来源：①每天签到+每日任务；②植物探险、碎片挑战每天打完；……
```
