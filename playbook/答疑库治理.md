# 答疑库治理（条目格式 / 置信度 / 合并裁决）

> 答疑库是这个 skill 最值钱的部分，也最容易被人写坏。本文规定：条目长什么样、id 怎么定、置信度怎么算、两人写的条目撞了谁说了算。

## 场景
答疑库现在**同时存在两种形态**：`qa/答疑库.md`（单文件，兼容回退，只剩本机读）与 `qa/entries/<id>.md`（一条一文件，真源）。**新条目一律进 entries 目录**；单文件已 **不随仓库发布**（2026-11-26 起），留在本机只当 `entries/` 为空时的兜底。
拆开的原因：原来 192 条挤在一个 76KB 文件里，两人同时加条目必冲突，diff 是一整坨看不出改了哪条；拆开后不同人加不同条目 → 不同文件 → 零冲突，同一条两人都改 → 冲突范围只有这一条。

## 现象
| 问题 | 表现 |
|---|---|
| 改了问法 | 被当成新条目，旧条目还在 → 同一问题两条答案并存 |
| 要点写成整段话 | 一段话没法单独评价，置信度只能整条给 |
| 两条字面很像 | 「困难6怎么过」和「困难8怎么过」被合成一条 → 答的是另一个关卡 |
| 社区沉淀被当权威 | 直接给「可信」档 → 玩家拿到没核实过的结论 |

## 原因
| 问题 | 原因 |
|---|---|
| 改了问法 = 新条目 | id 是**首次入库按问法 slug 生成后固化在文件里**的；不固化 → 系统按问法重算 |
| 要点不可评价 | 要点必须是「一个可独立评价的具体说法」，写成整段就没法逐点打分 |
| 字面像 ≠ 语义同 | `keyNumbers()` 抽关卡号/钻数/阶数，数字不同就是**否决闸**，直接不许合并 |
| 社区沉淀被当权威 | 社区来源聚合最高只到 80（高置信度），**可信档 90+ 只给官方资料/人工核实** |

## 做法
**条目格式（一条一文件）** —— `qa/entries/q-买了塔黄无尽用什么好.md`
```markdown
---
id: q-买了塔黄无尽用什么好
question: 买了塔黄无尽用什么好
keywords: [塔黄, 无尽, 保龄球, 卡波, 阵容]
version: 通用
confidence: 70
updated: 2026-11-25
source: https://www.taptap.cn/moment/873346111618682030
---

## 要点
- [70%] 优先买神器保龄球
  - 来源: https://www.taptap.cn/moment/873346111618682030
- [50%] 卡波建议塔黄空吸到最高再点下一波
  - 来源: https://www.taptap.cn/moment/873346111618682030
```
frontmatter 七字段：`id / question / keywords / version / confidence / updated / source`；正文是 `## 要点` + 每条 `- [NN%] 要点文本` + 缩进的 `- 来源: URL`。没有 `## 要点` 段的旧格式也兼容：整段正文算**唯一一个要点**。
**id 纪律**
- id 由问法 slug 生成，**首次入库后固化写进文件**；问法后来改了，**id 不改**（改 id = 系统当成新条目，旧条目变僵尸）；同 id 但来源完全不同 → **拆成两个 id**，不要塞进同一条
- 人工加的条目要跑一次 register，否则 30 天没被引用会被归档：`node scripts/qa-admin.mjs register --id <id>`
**要点（claim）纪律**
- 一个要点 = **一个可独立评价的具体说法**；不拆成词/短语；数字 / 名称 / 机制**原样保留**（"1800钻" 不能写成 "一千八左右"）
- 一段答案 **1~6 条**要点；超过 6 条说明问题太散，先拆问题
**置信度五档**：不可信 0-10（弃答）/ 低置信度 10-40（弃答、待核实）/ 中置信度 40-60（降档口语："我印象里""听说"）/ 高置信度 60-90（准话）/ 可信 90-100（准话）。
**聚合规则**（`lib/qa-entry.mjs` 的 `aggregateClaimConfidence`）
| 证据形态 | 聚合置信度 |
|---|---|
| 官方资料 / 人工核实 | **95** |
| 有未解决的反对票 | **30** |
| >3 个独立渠道 且 ≥3 个玩家说法一致 | **80** |
| ≥2 个独立渠道一致 | **70** |
| 单一来源 | **50** |

**社区沉淀最高只到高置信度（80）**；可信档（90+）只有官方资料和人工核实能进。
**合并裁决**
| 情形 | 裁决 |
|---|---|
| 自动沉淀（有 source）vs 自动沉淀 | `updated` 新的赢，旧的进归档 |
| 人工（无 source）vs 人工 / vs 自动 | 正文取长 + 关键词取并集；人工内容保留，并入自动沉淀的来源 |
| 两者冲突 | 写 `qa/归档/答疑库-合并冲突-YYYY-MM-DD.md`，等人复核 |

**任何情况下都不覆盖高置信度要点** —— 新答案只能作为**补充要点并列**。合并命令：`node scripts/qa-merge.mjs --status` / `--dry-run` / `--apply`。
**防止误合并**：`keyNumbers()` 抽关卡号/钻数/阶数，两边数字对不上就是**否决闸**。「困难6怎么过」vs「困难8怎么过」字面极像、语义完全不同，靠的就是这条。
**写库前必过的质量闸**：`node scripts/qa-lint.mjs`（frontmatter/隐私/自签名）、`node scripts/qa-admin.mjs purge-tag --apply`（剔我们自己签名的脏条目）。必须挡住四类：① 垃圾（求码帖、加好友帖、纯广告）② 自签名（正文带「版主助手-小鲸鱼」）③ 隐私（手机号/邮箱/QQ 群号，公开客服 QQ 除外）④ 未脱敏（昵称写「社区玩家」或 `依******梦`；好友码/天宫码一律不写）。
**三条硬要求**：① **关键词写玩家的口语**，各种问法都列上（关键词是打分主依据，写书面语等于匹配不上）② **答案用玩家口气写**，短句口语 ③ **事实必须准**，数字/名称/机制不能编 —— **错答案会被自动发出去，比不回答更糟**。

## 这条内容该进哪一层（答疑 / 资料 / 素材）

| 你手上是什么 | 放哪 | 理由 |
|---|---|---|
| 「玩家问 X，我们答 Y」的现成答案 | `qa/entries/<id>.md` | 匹配到就照这个答，要求短、准、可直接发 |
| 机制 / 流程 / 活动规则（说不成一句答案） | `qa/资料/doc-<版块>.md` | 组答时当**参考材料**，模型自己组织话；按 `##` 分节独立取用 |
| 有信息量但还作不了答案的原始爆料/截图结论 | `qa/素材/raw-<主题>.md` | 只存档，**不参与组答**，等证据够了再升级成资料或条目 |
| 零引用 / 垃圾 / 求码帖 | `qa/归档/` | 只移动不删除；不进仓库 |

> 判断口径（大哥 2026-11-26）：「此类更像资料…回答是可以参考」 ——
> 说不成一句准话的机制类内容，**别硬塞进答疑库**，进资料库。

## 术语 / 黑话拿不准怎么办

游戏黑话是踩坑重灾区，已错过 4 次（原大、魔影甜菜、一豆三旗、令营）。规则：

1. **不确定就问大哥，别猜** —— 猜错的答案会被自动发出去，比不答更糟
2. 问清楚后**当场落到 `qa/资料/doc-glossary-*.md`**（植物/口诀/道具三类各一份），加一行就够
3. 同一个东西有多个叫法（原始大哥 = 原大），**两个都写成表里的独立行**，并在备注里写「同指一物」
4. 玩家/早期文档写错的叫法（「令营」），**写成关键词**用来接住错误问法，但正文明确写「没有这个叫法」

## 已知缺口（谁有空谁补）

| 缺口 | 现状 | 影响 |
|---|---|---|
| 自动沉淀**不拆要点** | `appendQaEntry` 硬写 `claims: [{text: 整段}]`，只有 `qa-admin submit`/`qa-resplit` 走 `splitClaims` | 沉淀条目的置信度是**条目级**，不是要点级，合并时无法逐点评价 |
| 每日自动合并**只有本地一条源** | `collab.remote.owner/repo` 为空 → `qa-merge --status` 只见 `local-runtime` | 多人合并实际没跑起来，得先填自己仓库再 `qa-merge --schedule` |
| 沉淀去重只看来源 URL | 同一问题不同帖 → 建两条 | 靠合并兜底，但合并没跑时会重复堆积 |

## 检查清单
- [ ] 新条目落在 `qa/entries/<id>.md`；frontmatter 七字段齐全，`id` 与文件名一致且是首次入库固化的
- [ ] 要点 1~6 条，每条一个可独立评价的说法，数字原样，每条带 `- 来源: URL`
- [ ] 置信度按聚合规则算，社区来源不超过 80；关键数字不同的条目没被合并（`--dry-run` 看过计划）
- [ ] 冲突进了 `qa/归档/答疑库-合并冲突-YYYY-MM-DD.md`
- [ ] `qa-lint.mjs` + `purge-tag` 跑过：无垃圾/自签名/隐私/未脱敏
- [ ] 关键词是口语、答案是玩家口气、事实能核
- [ ] 机制类内容没被塞进答疑库（该进 `qa/资料/`）；资料 keywords 已覆盖玩家口语变体
- [ ] 术语拿不准的地方**问过大哥**，结论落到 `doc-glossary-*`
