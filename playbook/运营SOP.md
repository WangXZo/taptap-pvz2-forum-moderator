# 运营 SOP（每日流程 / 限速闸 / 每日合并 / 人工介入）

> 版主助手每天怎么跑、什么时候必须停下来交给人、合并怎么不打架。数值全部取自 `scripts/config/schema.json` 的默认值。

## 场景
每天人工版主要做的事交给守护进程跑，跑完要人工抽查什么。这个 skill 的底线是：**宁可少答，不可答错** —— 错答案会被自动发到公开论坛。

## 现象
| 现象 | 含义 |
|---|---|
| 匿名读接口大面积失败 / 回复变慢 | 触发阿里云 WAF（**封禁窗口 >25 分钟**）；限速闸生效：降速 ×0.5 + 冷却 60s。别重启别重试 |
| 守护进程整段停摆 | 连续 3 次失败触发**硬刹车**，暂停所有发送 15 分钟 |
| `chat()` 返回 `{ok:false,error:'llm_daily_cap'}` | 今日 LLM 调用已到 300 次上限（按 UTC 日期重置） |
| 合并后库里多出看不懂的条目 | 合并把语义不同的条目合成了一条，或覆盖了高置信度要点 |

## 原因
| 现象 | 原因 |
|---|---|
| WAF | 匿名接口限流，探测太密就封 IP；三个数据源同时 120s 齐拉必炸 |
| 变慢 | `rateLimit.waf.cooldownMs` 冷却后 `perSecond = max(floor, base × 0.5)` |
| 整段停摆 | `rateLimit.waf.hardBrakeAfter=3` → `pauseMinutes=15` |
| 超闸 | `llm.dailyCallCap=300`，超了**快速失败转人工**，不硬编 |
| 合并出错 | 合并靠「稳定 id + 要点语义」认条目，认错就会合错 |

## 做法
**1. 每日流程（一条不落）**
| 步 | 做什么 | 命令 |
|---|---|---|
| 1 抓帖 | 按发布时间拉最新帖、三源错峰入队 | `node scripts/watch.mjs`（守护常驻，2 分钟一轮） |
| 2 答疑匹配 | 关键词 + 向量 + 相似度打分命中答疑库 | 同上（`collect.mjs` 内部完成） |
| 3 自动回复 | 命中且过语义确认门 → 驱动 Chrome 回复 + 表情 + 签名 | `node scripts/collect.mjs --dry-run` 先看会不会发 |
| 4 缺口报表 | 没命中的问题列出来，人工补库 | `node scripts/report-gaps.mjs` |
| 5 答疑库沉淀 | 社区已答的问题自动入库 | 守护每轮自动沉淀；体检 `node scripts/qa-lint.mjs` |
| 6 每日合并 | N 路合并并写回（见下） | `node scripts/qa-merge.mjs --schedule` |

**2. 守护模式的两个限速闸**
闸一 · WAF 自适应限速（`config.rateLimit.waf.*`）：检出 WAF → 立刻降速 **×0.5**（不低于 floor）+ 冷却 **60s**；每成功 **20** 次提速 **×1.5**；连续 **3** 次失败 → 硬刹车，暂停所有发送 **15 分钟**。
闸二 · 平台操作节奏：`watch.minOpGapMs` = **300ms**（平台操作最小间隔，同一点击别连发）；`watch.intervalSeconds` = **120s**（轮询/重排间隔，三数据源错峰，别齐拉）；`watch.maxPages` = 20（单轮 200 条上限，**别往上调，容易招 WAF**）。
**3. 每日合并的规矩**
- 在 `config.collab.merge.window` 指定的窗口（默认 **02:00~05:00**，本地时间）内**随机**取一个时刻执行 —— 目的是**避开多人同时拉取/提交**
- 锁文件 `data/merge-lock.json` 记录当日随机时刻与执行状态 → **一天只跑一次**
- 重复执行是**幂等**的（同输入同结果），重启补跑不会灌重复内容；手动补跑：`node scripts/qa-merge.mjs --apply --now`
**4. 合并的四路来源**
```
① GitHub main        别人合过的
② GitHub contrib/*   各人免 PR 直提的分支
③ 本地运行副本       守护进程自动沉淀的
④ 本地真源           手上正在改的
        ↓ N 路合并 → 写回 config.collab.merge.writeBack（github-main / local-runtime / local-src）
```

> ⚠️ **前置条件（2026-11-26 审计发现）**：上面 ①② 两路都靠 `collab.remote.{owner,repo}`。
> 这两项**默认是空的**，空的就只剩 ③④ 一路 —— 实测 `qa-merge --status` 只显示 `local-runtime 189 条`，
> `data/merge-lock.json` 从未生成过，等于**每日合并一直没真正跑**。
> 每个使用者在 `config.collab.remote` 填**自己的** owner/repo（不写死，各人渠道不同），
> 再把 `node scripts/qa-merge.mjs --schedule` 挂到系统计划任务，四路合并才算接通。

**5. 冲突怎么办**
- 不自动裁决的（人工条目正文不同、要点互相矛盾）→ 写进 `qa/归档/答疑库-合并冲突-YYYY-MM-DD.md`，**等人复核**
- **涉及高置信度要点的冲突一律等人**，机器不许裁；合并本身**不覆盖高置信度要点**，新答案只能作为补充要点并列
**6. 人工介入的边界（这五种情况停下交人）**
1. **模型渠道全挂** —— 不许退化成「凭印象编一个答案」
2. **答复涉及金钱 / 账号 / 封禁** —— 充值、退款、账号找回、封禁申诉一律人工
3. **玩家情绪激烈** —— 吵架、维权、差评升级，不接话
4. **语义确认门不通过** —— 匹配分不够 / 语义校验失败，一律不自动发
5. **连续 3 次操作失败** —— 停手，别重试刷接口
**7. 成本闸**：`config.llm.dailyCallCap` 默认 **300**（`0` = 不限），按 **UTC 日期**重置；超闸后 `chat()` 返回 `{ ok:false, error:'llm_daily_cap', capped:true, used, cap }`，**调用方转人工**，不硬编、不偷偷超额、不换渠道硬闯。
**8. 人工复核清单（合并后必做）**
合并后**抽查 3 条**：一条自动沉淀的、一条人工的、一条有冲突的。看两件事：要点有没有被**错误合并**（关键数字不同的两条不能合）、置信度是否**合理**（社区沉淀不该出现可信档 90+）。配套命令：`node scripts/qa-merge.mjs --status`（看四路差异）、`node scripts/qa-lint.mjs`（格式/隐私/自签名）、`node scripts/report-daily.mjs`（当天日报）。

## 检查清单
- [ ] 每日流程 6 步都跑了，缺口报表有人看
- [ ] 守护日志没有「降速 / 硬刹车」告警；硬刹车要查 WAF 而不是重启
- [ ] 平台操作间隔 ≥300ms，轮询 120s，三源错峰，翻页上限 20
- [ ] 合并在 02:00~05:00 窗口内随机时刻执行，`data/merge-lock.json` 记着当日状态
- [ ] `qa/归档/答疑库-合并冲突-YYYY-MM-DD.md` 里的冲突已人工复核，高置信度冲突一律等人
- [ ] 五种人工介入情况发生时确实停了，没有硬答；`llm_daily_cap` 触发时转人工了
- [ ] 合并后抽查 3 条（自动/人工/冲突各一条）过了
