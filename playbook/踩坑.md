# 工具链与环境的坑（2026-11-25 沉淀）

> 固定组合：Windows + PowerShell 5.1 + DSH 沙盒（workspace-write）。下面 8 个坑的错误码都不直观，排查一次十几分钟。

## 场景
- 在 DSH 里跑 Node 脚本、写 `.ps1` 小工具、往 GitHub 推答疑库时踩到的环境问题：表现像「脚本逻辑写错」，实际全是工具链边界。
- 两处边界：**沙盒权限**（能不能写、能不能捕获子进程输出）、**Windows 编码与网络**（PS 5.1 读 UTF-8、到 github.com 的 TLS 被 RST）。

## 现象
| # | 坑 | 症状 / 报错 |
|---|---|---|
| 1 | 沙盒下 Node 捕获子进程输出 | 脚本没输出直接挂：`Error: spawnSync ... EPERM` |
| 2 | PS 5.1 读无 BOM UTF-8 脚本 | 中文乱码 → `The string is missing the terminator` / `You must provide a value expression following the '/' operator` |
| 3 | 到 github.com 的 HTTPS 被重置 | git/curl 报 `Connection was reset`，`gh` 却通 |
| 4 | GitHub API 推空仓库 | 409 `Git Repository is empty` / 422 `Update is not a fast forward` |
| 5 | git 中文路径被转义 | `"qa/\347\255\224..."` → 拼路径读不到文件 |
| 6 | `gh --jq` 被吞引号 | `function not defined`（`.a` 被当成函数名） |
| 7 | PowerShell 读 UTF-8 文件 | `Get-Content` 里中文全是 `??` |
| 8 | 沙盒写工作区外路径 | 写 `~/.dsh/`、`C:\Users\...` → `Access Denied` |

## 原因
| # | 真正原因 |
|---|---|
| 1 | 沙盒禁止程序间建管道去**捕获**另一程序的 stdio；`stdio:'inherit'/'ignore'` 不建管道所以不受限，PowerShell 自己的管道也不受影响 |
| 2 | PS 5.1 按 ANSI 码页（936/1252）解码无 BOM 文件，乱码里的引号/反斜杠破坏字符串边界，报错位置与病因完全对不上 |
| 3 | DNS 正常、TCP 443 也连得上，但 TLS 握手被 RST；`gh` 走另一条链路 |
| 4 | 空仓库没有 ref，`/git/blobs` 无处挂载；不带 parent 的 commit 是「另起一条历史」，ref 不是快进 → 422 |
| 5 | git 默认 `core.quotepath=true`，非 ASCII 路径按 C 风格八进制输出 |
| 6 | PowerShell 先处理双引号，`--jq '.a == "b"'` 里的 `"b"` 被剥掉 |
| 7 | `Get-Content` 默认按 ANSI 解码（5.1），无 BOM 的 UTF-8 直接乱码 |
| 8 | 沙盒只允许写工作区 `E:\work\AI\deepseek-workspace` 与平台临时目录 |

## 做法
**1. 要「跑子程序并拿它的输出」时怎么选**
Node 里 `execFileSync`/`spawnSync` 捕获别的程序输出 → 沙盒里必 `EPERM`；改用 `spawn(..., { stdio:'inherit' })` 或 `{ stdio:'ignore' }`。
```powershell
$out = & python scripts/server.py 2>&1 | Out-String   # ✓ PowerShell 管道不受这条限制
```
确实必须由 Node 捕获 stdout → 申请 `danger-full-access`（写明要做什么/为什么/影响范围），别改成「让用户自己跑」。
**2. `.ps1` 一律存成 UTF-8 with BOM**（乱码报错定位完全对不上，先修编码再查语法）
```powershell
$p = 'E:\work\AI\deepseek-workspace\...\scripts\foo.ps1'
$t = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $t, [System.Text.UTF8Encoding]::new($true))  # BOM
```
**3. github.com 被重置 → 远端读写走 API，不走 git**
```powershell
Test-NetConnection github.com -Port 443      # TcpTestSucceeded: True（DNS 也正常）
curl.exe -I https://github.com               # Connection was reset
git ls-remote https://github.com/<owner>/<repo>.git   # Connection was reset
gh api user                                 # 通 → 是 git/curl 这条链路被掐
```
改用 `gh api ...` 或直连 `https://api.github.com/...`，**不要**用 `git fetch/push`。
**4. GitHub API 推空仓库：先建分支，commit 必带 parent**
```powershell
$Owner='<owner>'; $Repo='<repo>'
$seed = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("pvz2 qa"))
gh api --method PUT "repos/$Owner/$Repo/contents/README.md" -f message="chore: init" -f content="$seed" -f branch="main"   # ① 建出 main，否则 /git/blobs 409
$parent = (gh api "repos/$Owner/$Repo/git/ref/heads/main" | ConvertFrom-Json).object.sha   # ② 当前 main 的 sha（不带它 → 422）
$blob   = gh api --method POST "repos/$Owner/$Repo/git/blobs" -f content="$b64" -f encoding="base64" | ConvertFrom-Json
$tree   = gh api --method POST "repos/$Owner/$Repo/git/trees" -f tree="[{`"path`":`"qa/entries/x.md`",`"mode`":`"100644`",`"type`":`"blob`",`"sha`":`"$($blob.sha)`"}]" | ConvertFrom-Json
$commit = gh api --method POST "repos/$Owner/$Repo/git/commits" -f message="feat: qa entry" -f tree="$($tree.sha)" -f "parents[]=$parent" | ConvertFrom-Json
gh api --method PATCH "repos/$Owner/$Repo/git/refs/heads/main" -f sha="$($commit.sha)" -F force=false
```
**5~7. 三条一行修**
```powershell
git -c core.quotepath=false diff --name-only                                   # 5 中文路径
$j = gh api "repos/$Owner/$Repo/contents/qa" | ConvertFrom-Json                # 6 弃用 --jq，改 PS 侧解析
$t = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false)) # 7 读 UTF-8
```
**8. 写工作区外：工作区中转 + 1 次提权**
① 在 `E:\work\AI\deepseek-workspace\2026-10-25-taptap-pvz2-moderator\work\` 下做副本 → ② 在工作区改完 → ③ 一次性申请 `danger-full-access` 把整目录复制回 `~/.dsh/skills/...`。列成一张清单一次复制，别每个文件申请一次。
