# 签名识别 + 玩家喊我们（summon）

> 用户 2026-10-29 明确要求：
> 1. 「多人回复问题，直接按照签名识别吧（当前签名：版主助手-小鲸鱼，注意匹配「与」，防止玩家喊你也被忽略）」
> 2. 「如果发现玩家喊你，过去，根据语义互动一下玩家（注意包括触发敏感等，拒绝。
>    如无触发规则，正常鼓励、赞扬、欣赏，同情等，不能贬低、辱骂等）」

---

## 一、为什么要有「签名识别」

答疑组是**多人**值班，同一个签名会出现在好几个账号的回复里。
以前只看 `myUserId` → 队友的回帖被当成「没人回过」→ 同一个问题被两个人各回一遍。

现在改成两道判据（`lib/signature.mjs` 的 `isOurComment`）：

| 判据 | 说明 | 可靠性 |
|---|---|---|
| 作者在团队名单里（`myUserId` + `config.teamUserIds`） | 最直接 | 高 |
| 正文**以签名结尾**（或签名独占一行） | 队友的 id 我们不一定有，靠签名兜住 | 中 |

### 归一化：括号 / 空格 / 连字符 / @ 全不讲究

```js
squash('「版主助手-小鲸鱼」')  === '版主助手小鲸鱼'
squash('@版主助手 小鲸鱼')    === '版主助手小鲸鱼'
squash('【版主助手-小鲸鱼】')  === '版主助手小鲸鱼'
```

- 去掉：`「」『』【】[]（）()<>《》""''` + `@＠`
- 去掉：空白 + `- – — _ · • ~ ／ \`
- 标签来源：`reply.signature`（完整 + 去括号内文）+ 兜底 `版主助手`/`小鲸鱼` + `summon.aliases`

> ⚠️ `summon.aliases` 是**自己的其它昵称**，属于个人信息 → 进仓库前必须脱敏（见 SKILL.md 脱敏规范）。

## 二、「我们回过」vs「玩家在喊我们」

这是本模块最关键的一张表 —— **分错了就会把玩家的求助当成「已经回过了」直接跳过**。

| 玩家/我们说的原文 | 判定 | 理由 |
|---|---|---|
| `答案正文\n\n「版主助手-小鲸鱼」` | **我们的回复** | 签名独占一行 |
| `大佬牛逼 「版主助手-小鲸鱼」[表情_点赞]` | **我们的回复** | 单行以签名结尾，前面有实质内容 |
| `谢谢小鲸鱼` | 玩家在喊我们 | 只有客套词 |
| `小鲸鱼` | 玩家在喊我们 | 光秃秃一个称呼 |
| `小鲸鱼在吗` | 玩家在喊我们 | 签名在句首，不在结尾 |
| `@版主助手-小鲸鱼 困难6怎么过` | 玩家在喊我们 | 同上 |
| `版主在吗` | 玩家在喊我们 | 泛称 + 呼叫语气（`matchRoles`） |
| `这个是之前版主说过的` | 不用理 | 泛称但没有呼叫语气 |

实现：

- `isOurReplyText(text, config)` —— 是不是我们发的
- `isSummonText(text, config)` —— 是不是玩家在喊我们（`{summon, why: 'signature'|'role', alias}`）

`why` 用来排序：**点名签名的优先于只喊「版主」的**。

## 三、8 个语义桶（`lib/summon.mjs`）

判定顺序（先命中先返回）：

```
sensitive → thanks → praiseMe → complain → celebrate → help → greet → other
```

| 桶 | 触发词（节选） | 回什么 | 表情池 |
|---|---|---|---|
| `sensitive` | 退款 客服 补偿 封号 被封 举报 充值 消费 申诉 投诉 外挂 破解 私服 卖号 交易 维权 … | **礼貌拒绝**：只说「这我管不了 / 得走官方」，**不给建议、不表态、不承诺** | 叹气 不好意思 捂脸哭 冷漠 委屈 |
| `thanks` | 谢谢 感谢 多谢 谢了 3q | 不客气、应该的 | 比心 送花 开心 可爱 点赞 |
| `praiseMe` | 版主辛苦 负责 用心 靠谱 … | 谦虚（别飘） | 羞涩 可爱 不好意思 星星眼 比心 |
| `complain` | 闪退 崩溃 卡顿 掉线 打不过 太难 服了 心态崩 | 同情、共情、安慰 | 加油 比心 叹气 祈祷 泪目 |
| `celebrate` | 终于 通关 打过了 满级 稳了 | 一起开心、夸他 | 点赞 星星眼 加油 酷 大笑 |
| `help` | 怎么 如何 请问 求助 有没有 … | 库里有 → 用库的答案；没有 → **诚实说不知道** + 鼓励 | 捂脸哭 思考 加油 汗 祈祷 |
| `greet` | 在吗 你好 呼叫 有人吗 | 打个招呼 | 开心 可爱 wink 举手 期待 |
| `other` | 其余 | 温和接住 | 开心 可爱 狗头 吃瓜 微笑 |

文案池每类 **16 套**（测试里有 ≥15 的下限断言，只能加不能减），全部**单行**。

## 四、三条硬护栏

`assertKind(text)` 在发送前必过（还有 `assertNoLeak` 泄露自检）：

1. **不贬低、不辱骂、不嘲讽** —— 禁词：傻 蠢 笨 弱智 脑残 废物 垃圾 滚 闭嘴 菜鸡 丢人 活该 懒得理 不关我事 爱信不信 …
2. **不替官方承诺** —— 禁词：保证 肯定修 一定修 会补偿 内部消息 官方说了 包过 百分百 …
3. **事实只来自答疑库** —— 命中就用库的答案（一个字不改），没命中就只安慰

## 五、答疑库作答：先去掉称呼

```
「小鲸鱼，困难6怎么过啊」 → stripAddress → 「困难6怎么过啊」 → 再 matchPost
```

不去掉称呼的话，二元组分母变大、关键词命中没变 → 分数被稀释 → 本该命中的却只能回一句「我不敢乱猜」。

喊话场景的阈值单独给：`summon.qaScore`（默认 **0.6**，常规自动回复是 0.65）。
理由：玩家是**点名问我们**的，短问句本来就该放宽一点；而分数里的相似度项已经封顶，
所以 0.6 实际要求的是「关键词命中 + 问法高度相似」，不松。

## 六、执行与记账

| 环节 | 位置 |
|---|---|
| 挑喊话评论 | `collect.mjs` 的 `pickSummons()` —— 排除我们/队友发的、排除已回应过的 |
| 生成文案 | `lib/summon.mjs` 的 `buildSummonReply()` |
| 发送 | `lib/summon-send.mjs` → 复用 `lib/reply-nested.mjs` 的 `replyToComment()`（点「回复」→ 填文 → 插表情 → 发送 → 核验） |
| 记账 | `state.posts[id].summonReplied`（已回应的评论 ID）+ `state.recentReplies`（防重样） |
| 上限 | `summon.maxPerRun`（单轮，默认 3）/ `summon.maxPerPost`（单帖，默认 1） |
| 报表 | `reports/questions.md` 的「本轮喊话互动」明细表 |

失败或超上限 → `state.posts[id].summonPending = true` → 下一轮会重新读评论再试。
