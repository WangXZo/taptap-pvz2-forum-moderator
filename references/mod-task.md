# 版主管理任务（mod-task）

> 用户 2026-10-29 需求：
> 「新增，版主管理任务，检查最新的10条帖子。（注意该内容，使用短冷却检查，处理完等待1s后立即进行下一个）
> 　将存在"加好友"、"一起玩"、"好友位"等加好友行为，统一回复一下内容。并移除该帖。」
> 补充确认：**「移除」不是删帖** —— 用的是 TapTap 的「论坛管理 → 移除」，内容仍在、可恢复；
> 确认弹窗要**自动点掉**。

---

## 一、每轮做什么

```
1. 一次请求拉最新 10 条（sort=created，接口上限就是 10）
2. 逐条判定「是不是加好友行为」
3. 命中的：① 先回固定文案 → ② 确认发出 → ③ 再「论坛管理 → 移除」→ ④ 自动点确认框
4. 处理完等 1s（短冷却），立刻处理下一个
```

顺序是硬要求：**回复失败就不移除**（`replyOne` 失败 → 标「转人工」，帖子留着）。

## 二、判定规则（宁可漏，不可错）

| 类别 | 词 | 规则 |
|---|---|---|
| 强特征 | 加好友、好友位、好友码、好友、互加、互关、加群、拉群、加微、加v、加我、邀请码、二维码 | 命中即处理 |
| 弱特征 | 一起玩、找人一起、求一起、组队一起 | **必须同时带邀请码**才处理 |
| 裸码帖 | 正文只有一个 `andXXXXXX` | 处理 |
| 排除词 | 官方、公告、攻略、教程、招募、组队、开黑、缺人、主播、直播、兑换码、天宫码… | 命中就放过 |

邀请码 = TapTap 分享码，形如 `and5ZM3TJ2K`（`and` + 6~12 位字母数字）。

为什么要分强弱：现场真实的「一起玩困难9，缺个人」是**正常组队帖**，
但「andEAMVCZ49 9051824640 一起玩吧」是广告 —— 差别就在有没有邀请码。

```js
// scripts/lib/mod-task.mjs
detectFriendRequest({ title, text }) → { hit, keyword, inviteCode, reason }
```

## 三、页面操作（2026-10-29 实测）

帖子详情页右上角三个图标：**盾(反馈) / 剪刀(管理) / ⋯(更多)**。

| 步骤 | 选择器 / 判据 |
|---|---|
| 打开管理菜单 | `button[aria-label="管理"]`（就是剪刀那个）→ 派发 mousedown→mouseup→click |
| 点「移除」 | 菜单里文字**恰好等于**「移除」的可见叶子元素 → 往上找可点的祖先再派发事件 |
| 二次确认框 | `.tap-media-modal`，文案「是否确认将内容从论坛移除？」，按钮是 **「取消」/「移除」** |

⚠️ **确认按钮就叫「移除」，不是「确定」** —— 而且**不能全页找「移除」**，
否则会点到刚才那个下拉菜单项。必须**在弹窗范围内**找。

### 核验的坑

移除成功后：**帖子详情页还能打开**，标题、正文、评论都还在，只有版块列表里没有了。
所以判据是「点到了确认按钮」+「页面有成功提示」，**不能拿标题做依据**。

想确认真被移除了，用：

```bash
node scripts/post-admin.mjs check-removed <momentId>
```
（它翻版块列表查这个 id 在不在）

## 四、命令

```bash
node scripts/mod-task.mjs                # 真跑（回复 + 移除）
node scripts/mod-task.mjs --dry-run      # 只判定，看看会动哪些帖子
node scripts/mod-task.mjs --only <id>    # 只处理某一条（调试）
node scripts/mod-task.mjs --top 10       # 检查条数（默认 10）
```

守护循环里每轮答疑之后自动跑一次（`scripts/watch.mjs`）。
dry-run / `--no-reply` 时只判定不动作。

## 五、配置

```json
"modTasks": {
  "enabled": true,
  "friendRequest": {
    "enabled": true,
    "topN": 10,
    "cooldownMs": 1000,
    "reply": "你好呀～好友码集中贴已经置顶啦……👉 https://www.taptap.cn/moment/864806259805654695，能被更多人找到～"
  }
}
```

`reply` 换掉就是换统一话术；`cooldownMs` 是「处理完等多久再下一个」（用户要求 1s）。

## 六、记账与幂等

`state.posts[id].modTask`：

| 字段 | 含义 |
|---|---|
| `repliedAt` | 固定文案发出时间 —— **有值就跳过回复**（中途失败重跑不会重复回） |
| `removedAt` | 移除成功时间 —— 有值就不再处理这条 |
| `keyword` / `inviteCode` | 命中了什么，为什么命中 |
| `failed` | 回复失败的阶段（`no_input` / `fill` / `no_send_button` …） |

回完立刻落盘（不等移除），这样即使移除那步炸了，重跑也不会重复发同一段话。
移除没生效也不怕：帖子还在版块里，下一轮会被重新检出并重试移除（回复会跳过）。
