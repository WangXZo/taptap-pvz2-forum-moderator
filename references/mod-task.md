# 版主管理任务（mod-task）

> 用户 2026-10-29 需求与三次澄清：
> 1. 「新增，版主管理任务，检查最新的10条帖子…处理完等待1s后立即进行下一个。
> 　 将存在"加好友"、"一起玩"、"好友位"等加好友行为，统一回复一下内容。并移除该帖。」
> 2. 「先回复固定文本，确认发送后，再移除（注移除不等于删帖）」「移除有确认操作，请知悉自动点击确认」
> 3. 「我发现，你有误识别。请**仅限"存在加好友意图"**」
> 4. 「活动组队（十月同游/组队/一起玩）= 游戏内新增好友功能 → 不算」「活动邀请码 → 不算」
> 5. 「所有检查"好友意图"应跳过，有"官方版主"标识的帖」
> 6. 「这个要持续运行，检查无加好友行为，等待 2 分钟」「只会出现在今天及以后（功能今天上线）」

---

## 一、每轮做什么

```
扫目标子版块（默认：活动报名 + 讨论区）
  → 只取「今天 00:00 之后」的帖（历史帖一律不碰）
  → 逐条判定「是不是明确的加好友意图」
  → 官方/版主/自己发的帖：跳过（连看都不看）
  → 命中的：① 回固定文案 → ② 确认发出 → ③「论坛管理 → 移除」→ ④ 自动点确认框
  → 处理完等 1s，立刻下一个
```

**顺序是硬要求**：回复失败就不移除（标「转人工」，帖子留着）。

## 二、判定：只认「加好友意图」

两层结构：**意图模式命中** 且 **排除模式没命中**。

### 意图模式（明确在拉人加好友）

```
加(个|我|一下|点)?好友   快来加好友   好友位   好友码   好友群   好友邀请
扩列   互加   互赞好友   好友互赞   互关好友   求好友   蹭好友
有人加不   好友来加我   加群   拉群   加微   加威信   加v
```

补充规则：

- **标题整体就是好友类词**（标题只写「好友」「互赞」「扩列」）→ 算
- **裸好友码**（整篇只有一个 `andXXXXXX`）→ 算（`bareCodeIsIntent` 可关）
- 只有活动邀请码（纯数字码）→ **不算**

### 排除模式（命中就放过 —— 全部来自用户澄清）

| 类别 | 例子 |
|---|---|
| 活动组队（游戏内新增好友功能） | 十月同游 / 组队 / 组小队 / 一起玩 / 一起做任务 / 来进队吗 / 缺人 / 开黑 / 招募 |
| 活动邀请码互填 | 邀请码 / 互填 / 求互帮 / 义父 / 求求了 / 跪求 / 帮忙填 / 新人互助 |
| 游戏功能里的「好友」 | 好友宝箱 / 好友度 / 好友奖励 / 好友系统 / 好友商店 / 好友积分 |
| 正当内容 | 官方 / 公告 / 攻略 / 教程 / 版本更新 / 主播 / 直播 / 反馈 |

> ⚠️ **不能把裸「好友」当意图词** —— 「感觉好友宝箱的奖池缺少大货」就是这么被误判的。

### 官方/版主的帖：直接跳过

`checkAuthor(moment, { myUserId })` 四道判据，任一命中就跳过：

| 判据 | 说明 |
|---|---|
| `author.user.is_moderator === true` | 版主（集中贴「拓维游戏」就是这种） |
| `moderator_type > 0` | 官方号 / 创作者 |
| 作者 id === `myUserId` | 自己发的 |
| 作者名含 官方/版主/管理组/答疑组/运营 | 字段变了的兜底 |

> 血的教训：**集中贴标题里就有「好友码」**，不挡官方的话第一个被回复+移除的就是它。

## 三、持续运行：2 分钟一轮 + 待办队列（新帖优先）

用 `scripts/mod-watch.mjs`（**独立进程、独立 opencli session**，不和答疑守护抢标签页）。

用户 2026-10-29：「**优先处理，新的帖子。**」「**每轮都按照"新帖优先"重新获取，重排队列。**」

一次要清 100+ 条时，如果一轮全做（半小时），期间进来的新帖会被压在后面。所以：

```
每轮：① 重新扫（游标增量，只取新增）→ 官方/版主跳过 → 命中的并进队列
      ② **整队按发布时间倒序重排**（不是只把新帖插队首 —— 那样顺序会随轮次漂移）
      ③ 只处理队首 maxPerRound 条（默认 20）→ 一轮几分钟内结束
      ④ 队列存 state，中断/重启都不丢
```

队列 `state.modTask.backlog` 每轮都会**去重 + 重排**，所以「最新永远在最前」是恒定成立的。
`publishTime` 缺失时用 moment id 倒序兜底（id 随时间递增）。

**游标（cursor）** 记「上次扫到哪里」：按**发布时间**记，不按 id（帖子被移除后 id 就查不到了）。
每轮从最新开始扫，扫到游标就停 → 只处理新增的，接口请求量最小。

三条必须记住的坑：

1. **游标要在「整轮处理完」之后才落盘**。
   扫完就推进游标、然后中途被打断 → 下一轮会「到边界了」把剩下的帖整段跳过（丢帖）。
2. **停止判据要用「进入本轮时的游标」**，不能用循环里持续更新的那个值 ——
   feed 是时间倒序，每扫一篇游标都会变旧，拿它当停止线的话第二篇就被误判成已扫过。
3. **处理过的要从队列里摘掉**（不管成功没成功），否则失败的会无限重试刷屏。

跨天自动重扫（游标里存了日期）。补处理历史用 `--reset-cursor`。

## 四、页面操作（2026-10-29 实测）

帖子详情页右上角三个图标：**盾(反馈) / 剪刀(管理) / ⋯(更多)**。

| 步骤 | 选择器 / 判据 |
|---|---|
| 打开管理菜单 | `button[aria-label="管理"]`（剪刀那个）→ 派发 mousedown→mouseup→click |
| 点「移除」 | 菜单里文字**恰好等于**「移除」的可见元素 → 往上找可点的祖先再派发事件 |
| 二次确认框 | `.tap-media-modal`，文案「是否确认将内容从论坛移除？」，按钮是 **「取消」/「移除」** |

⚠️ **确认按钮就叫「移除」，不是「确定」** —— 而且**不能全页找「移除」**，
否则会点到刚才那个下拉菜单项。必须**在弹窗范围内**找，并排除「取消」。

### 核验的坑

移除成功后**帖子详情页还能打开**，标题、正文、评论都还在，只有版块列表里没有了。
所以判据是「点到了确认按钮」+「页面有成功提示」，**不能拿标题做依据**。

想确认真被移除了：`node scripts/post-admin.mjs check-removed <momentId>`。

## 五、命令

```bash
node scripts/mod-watch.mjs                 # 常驻（默认 120s 一轮）
node scripts/mod-watch.mjs --reset-cursor   # 首轮回溯重扫今天全部
node scripts/mod-watch.mjs --once --dry-run # 只跑一轮，看看会动哪些帖子

node scripts/mod-task.mjs                   # 单轮，真执行
node scripts/mod-task.mjs --dry-run         # 单轮，只判定
node scripts/mod-task.mjs --only <id>       # 只处理某一条
node scripts/mod-task.mjs --target activity_signup   # 只查某个子版块
node scripts/mod-task.mjs --sweep           # 强制全量重扫（无视游标）
```

## 六、配置

```json
"modTasks": {
  "enabled": true,
  "intervalSeconds": 120,
  "session": "tapmod",
  "targets": [
    { "groupId": 40173, "type": "activity_signup", "label": "活动报名" },
    { "groupId": 40173, "type": "feed", "label": "讨论区" }
  ],
  "friendRequest": {
    "enabled": true,
    "scope": "today",
    "cooldownMs": 1000,
    "maxPerRound": 20,
    "backlogMax": 500,
    "maxPages": 4,
    "maxSweepPages": 30,
    "bareCodeIsIntent": true,
    "reply": "你好呀～好友码集中贴已经置顶啦……👉 https://www.taptap.cn/moment/864806259805654695，能被更多人找到～"
  }
}
```

`type=activity_signup` 就是 `?sub_type=activity_signup` 那个「活动报名」子版块
（同一个 group_id，换 `type` 参数）。

## 七、记账与幂等

`state.posts[id].modTask`：`repliedAt`（有值就跳过回复）/ `removedAt` / `keyword` / `inviteCode` / `failed` / `stage`。

回完**立刻落盘**（不等移除），这样即使移除那步炸了，重跑也不会重复发同一段话。
移除没生效也不怕：帖子还在版块里，下一轮会被重新检出并重试移除（回复会跳过）。
