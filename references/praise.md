# 夸答题玩家（楼中楼）

> 代码：`scripts/lib/praise.mjs`（挑对象 + 组文案）、`scripts/lib/reply-nested.mjs`（楼中楼发送）
> 回归测试：`scripts/test-praise.mjs`（34 条断言）

## 什么时候夸

**只有一个条件**：某个提问帖里，**其他玩家给出了有效回答**。

不夸的情况（全部忽略）：

- 不是提问帖（攻略、组队、贴码、分享…）
- 「有效回答」不达标（见下）
- 回答的人是我自己
- 回答的人是版主 / 答疑组（夸同行没意义）
- 这条回答之前已经夸过（`state.posts[id].praisedComments` 记着评论 ID）

## 「有效回答」的门槛

在 `summarize.mjs` 的 `isUsefulAnswer`，**沉淀答疑库**和**夸奖**用的是同一把尺子 —— 不合格的答案既不污染答疑库，也不值得夸。

| 挡掉 | 判据 | 真实例子 |
|---|---|---|
| 太短 | 去表情后 < 12 字 | 「不是氪这么多」 |
| 客服引导 | 客服/找官方/退款/举报/充值/封号… | 「如果不行就找客服」 |
| 私下交换 | 私聊/加我/找我/互赞/互换/加群/联系方式… | 「谢了兄弟下个月找我」 |
| 贴兑换码 | 含 ≥6 位、含字母的字母数字串 | 「天宫码 JFA6Ds3Jcl」 |
| 纯反问 | 以 ? ？ 结尾且 < 20 字 | 「你是不是没有更新？」 |
| 没中文 | 没有中文字符 | 纯贴码 |
| 纯噪音 | 「顶/沙发/同问/哈哈哈…」 | 「顶」 |

> 这套门槛是**真发之前**补的。第一版没有它，脚本把「谢了兄弟下个月找我」「如果不行就找客服」都当成答案去夸了，还沉淀进了答疑库。

## 挑哪个对象

`pickPraiseTarget` 的排序：

1. 候选 = 所有回复里，作者不是我不是版主，且是有效回答
2. 按 `scoreReply` 打分排序：答疑/助人/专家徽章 +4、版主 +4、点赞数 ≤2、长度适中 +2、有具体数字 +1、反问 −1
3. 取最高分那条
4. **楼中楼的回答要挂到它父评论下**（浏览器里能点「回复」的只有一级评论），`targetCommentId = parentId || id`

## 文案与表情

口吻要求（详见 SKILL.md「说话的口吻」）：**口语化、亲切、多样**。

```
✅ 「哇~依星&寻梦大佬，牛逼[表情_点赞]」
✅ 「有123大佬在，新手有救了[表情_点赞]」
❌ 「感谢 依星&寻梦 的热心解答，讲得很清楚，帮到不少人[表情_点赞]」  ← 客服腔，已被打回
```

夸奖模板按四种口味混在一个池子里（`PRAISE_TEMPLATES`，现为 **18 套**）：

| 口味 | 例子 |
|---|---|
| 惊叹型 | 「哇~{name}大佬，牛逼」「好家伙，{name}大佬这也懂」「{name}大佬太顶了」 |
| 亲切感谢型 | 「懂了懂了，谢谢{name}大佬」「有{name}大佬在，新手有救了」「学到了学到了，{name}大佬靠谱」 |
| 服气点赞型 | 「{name}大佬，稳」「这回答给满分，{name}大佬」「就冲{name}大佬这句，我先试为敬」 |
| 轻调侃型 | 「{name}大佬，肝度有点猛啊」「这才是老玩家，{name}大佬」 |

选措辞的规则：

- 散列起点 = **昵称 + 答案开头** → 同一条回答永远同一处起算，重试不会跳变
- **最近说过的口气主动避开**：拿模板的固定片段去比 `usedTexts`，
  命中就把这几种口气整体挪到队尾再挑 → 连夸 8 个人是 8 种不同口气
- 已发过的文本（`usedTexts`，来自 `state.recentReplies`）也避开
- **每条模板都必须带昵称** —— 楼中楼里不点名就不知道在夸谁

> 为什么这么在意「不要模板化」：4 套时期，主页一翻就能看出规律 ——
> 「说得又准又细」出现 4 次、「感谢…热心解答」出现 3 次。玩家是会把版主所有回复翻一遍的。

表情按**回答内容**自动挑 1 个：

| 语境 | 表情 |
|---|---|
| ≥15 字且含数字（版本/关卡/血量） | `点赞` |
| ≥8 字且是教学建议口吻 | `比心` |
| ≥15 字的说明 | `星星眼` |
| 简短 | `开心` |

- **必须是单行**（楼中楼 `fill` 多行会把内容清空）
- **表情必须在句尾**（插入方式是「光标定位到末尾 → 点选表情」）
- 签名「版主助手-小鲸鱼」紧跟正文（同一行，排在表情之前），由 `config.praise.signature` 控制

改模板前后跑一次 `node scripts/test-praise.mjs`，里面有一组**口吻护栏**：
「没有客服腔」「每条都点名」「每条都够短」「30 个玩家至少 10 种说法」「同一人同一条回答措辞稳定」。

## 楼中楼操作流程（照着这个顺序做）

```
1. 打开帖子 → 滚到底（评论懒加载）
2. 找到评论项 .moment-post-item[data-comment-id="<id>"]
3. 展开楼中楼：
   - 先看条内有没有「发送」按钮 → 有就是已展开（别点，toggle！）
   - 没有才点 .moment-post__tool-reply 里的 svg/path（点外层 div 无效）
   - 轮询等「发送」按钮出现
4. fill 文案（单行）→ 读 innerText 校验写进去了
5. 插表情：
   a. 光标移到末尾
   b. 逐个试工具栏项 —— 但**跳过 @ 按钮和图片按钮**
      （表情按钮 = 唯一带 .tap-popover__trigger-wrap 的那个；
        @ 按钮的 SVG path 特征是 "M7.771 2.499"）
   c. 派发 mousedown→mouseup→click 到 .tap-popover__trigger-wrap
   d. 全页找 img[data-tap-editor-emoji-id][alt="<表情名>"] → 点它
   e. 校验编辑器里恰好 1 个 [表情_xxx] 节点
6. 点条内的「发送」→ 草稿清空才算发出去（否则派发事件再试一次）
7. 核验：先点开「展开剩余 N 条回复」，再在条内文字里搜自己的文案
```

## 踩坑清单（都是实测踩出来的）

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 评论数字段读错 | 评论永远读不到，沉淀/夸奖从不触发 | 读 `moment.stat.comments` |
| 2 | 用高度判断「楼中楼是否展开」 | 空编辑器高度为 0 → 误判没展开 → 再点一次反而关掉 | 看条内有没有「发送」按钮 |
| 3 | 表情面板按「评论项内」找 | 永远找不到，面板是页面级 portal | 全页找 `.tap-editor-emoji__popover` |
| 4 | 用 `.click()` 点表情按钮 | 面板不开 | 派发 mousedown→mouseup→click 到 `.tap-popover__trigger-wrap` |
| 5 | 逐个试按钮时点了 @ 按钮 | 文案里被插入一个 `@` | 排除 @ / 图片按钮，只认带 trigger-wrap 的 |
| 6 | 校验拿整条评论 innerText | 把输入框草稿当成已发送 → 假核验 | 只认回复列表文字 + 草稿已清空 |
| 7 | 用接口判断是否发出 | 接口不返回折叠的楼中楼 → 假阴性 → 重复发 | 浏览器侧核验，接口只作参考 |
| 8 | 多行 fill | 内容被清空 | 夸奖文案单行 |
| 9 | `oc().text` 混了 stderr | `Number()` 得 NaN、`JSON.parse` 失败 | 只取 `.out` |
| 10 | 新旧两版评论组件结构不同 | 一版能开一版开不了 | 用「发送按钮在不在」这种语义信号，别依赖 class 细节 |
