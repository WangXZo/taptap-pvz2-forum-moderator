### 社区已答复 → 自动沉淀答疑库

一个问题如果**社区里已有人回答**（且你没回过）：

1. 抓该帖所有回复（含楼中楼），滤掉「顶/同问/哈哈哈」这类噪音
2. **自动总结**：优先选带「答疑/助人/专家」徽章、版主、或内容最具体的回复；其他有信息量的作为「补充：」
3. 写入 `qa/答疑库.md`，带 `- 来源：<帖子链接>` 和 `- 总结时间：<时间>`
4. 该帖标记为 **✅ 已回复（他人已回复）**，不重复回

沉淀条目匹配分 ×0.9（低于人工条目），避免未复核的答案直接自动发出去。

**实测样例**（PVZ2 真实数据）：帖子「月球基地打完只给12个粗制抑能吗」有两条他人回复，自动选中带「答疑智多星」徽章那条「指正是碎片，错是给18个」入库，帖子标记已回复。

### 答疑库生命周期

使用统计放 `data/qa-usage.json`（不污染答疑库正文）：`cited`（引用次数）、`lastCitedAt`（最后引用）、`createdAt`（入库时间）。

**匹配优先级**（对应「优先用多次更新、多次使用、时间较新」）：

```
最终分 = 基础分 × 权重
基础分 = 关键词命中率×0.6 + 文本相似×0.4      （社区沉淀 ×0.9）
权重   = 1.0 + min(0.15, 引用次数×0.03)        ← 用得多
        + 0.05（7 天内引用）/ 0.02（30 天内）    ← 用得新
        + 0.03（人工维护）
```

**自动归档**：每月 **1~5 号**首次运行执行一次 —— 超过 **30 天未引用**的条目移到 `qa/归档/答疑库-冷数据-YYYY-MM.md`，主库重排。**只移动不删除**，随时可拷回恢复。

### 表情怎么写

回复正文里写 `[表情_开心]`，脚本自动展开成 TapTap 表情节点：

```markdown
## 问：什么时候能拿到新植物
- 关键词：新植物, 解锁
---
新植物按版本节奏开放，进图签就能看到预告啦[表情_开心]
```

- 可用 61 个标准表情，全表见 skill 的 `references/emojis.md`
- 不在表内 → 该条转「🖐 需人工处理」，**绝不发出错内容**
- 跨分组（洛克王国/王者联动表情）**不支持**，实测会插错

## 1. 四类标记（核心）

每条帖子最终只会落在这四类之一：

| 标记 | 含义 | 触发条件 |
|---|---|---|
| ⏳ **未回复待回复** | 命中 QA，等着发出去 | 分数 ≥ 0.75 且不在冷却期 |
| ✅ **已回复** | 已经发出回复 | 发送成功，或读评论发现你回过 |
| ➖ **无需回复** | 不该回 | 非提问帖 / 重复问题 / 早已回复 |
| 🖐 **需人工处理** | 机器判不了 | 未命中 QA / 分数 0.45~0.75 / 含敏感词 / 发送失败 |

报表 `reports/questions.md` 和 `questions.csv` 就按这四类分区，全部帖子累积收录。

## 2. 每轮做什么（一次请求）

```
① 发 1 次请求 → /feed/v7/by-group?from=0&limit=8&sort=created
   sort=created → 接口直接按发布时间严格降序返回，脚本不排序
② 取回即最新 8 条（接口已排好序）
③ 逐条判定：
     ├ 状态库里已「已回复」        → 跳过，不改状态
     ├ 状态库里已「无需回复」      → 沿用，不重复打扰
     ├ 是提问 且 首次见到        → 花 1 次请求查评论，确认你是否已回过
     └ 判定 → 四类之一
④ 对「未回复待回复」的 → 打开帖子 → 填内容 → 发送 → 改标记
⑤ 更新报表 → 睡 10 分钟 → 回到 ①
```

**关于请求量**：正常轮次只有 **1 次** 列表请求。只有当出现「新提问帖」时，才会额外发 1 次评论查询去确认你是不是已经回过了——这是防重复回复的必要开销，最多再多 8 次，通常为 0~2 次。

## 5. ⚠️ 踩到的坑：阿里云 WAF（必须知道）

我之前为了摸清参数，探测得比较密集，结果触发了 IP 级封禁：

```
<!doctype html><meta name="aliyun_waf_aa" content="...">
```

- HTTP 200，但返回的是 HTML 而不是 JSON
- **curl 和 Node fetch 同时被拦** → 是 IP 级，不是客户端问题
- 实测**封禁持续超过 25 分钟**仍未恢复

代码里已做处理：
- 识别拦截页 → 不重试无意义请求，退避 15s/30s/45s
- 仍失败 → **本轮直接跳过，打印「下轮再试」**，不刷日志、不影响守护进程活着

**对你的影响**：刚部署时如果接口是封着的，守护进程会一直空转直到解封，这是正常的，不要反复重跑。

## 9. QA 库怎么维护（对应「补充后自动回复」）

打开 `qa/qa-library.md`，照格式加：

```markdown
## 问：无尽模式怎么配植物
- 关键词：无尽, 无尽模式, 怎么配, 阵容, 推荐植物
- 版本：通用
---
无尽的核心是续航 + 单体爆发……
```

- `关键词` 是打分主依据，**写玩家真实会用的词**
- `---` 这行必须保留，它是正文起点
- 改完**不用改代码**，下一轮自动生效

链路：你加 QA → 下一轮重新匹配 → 之前判「需人工」的帖子可能变成「待回复」→ 自动发出。

> 注意：已被判为「无需回复」的帖子不会再翻案（避免重复打扰），需要人工用 `node src/reply.mjs --only <帖子ID>` 处理。

## 10. 安全阀

| 阀门 | 默认 | 作用 |
|---|---|---|
| `reply.dryRun` | `true` | 默认只预览不发 |
| `match.maxAutoReplyPerRun` | 8 | 单轮最多回 8 条 |
| `reply.blacklistWords` | 客服/申诉/退款/封号… | 命中转人工 |
| `match.minPostAgeMinutes` | 10 | 新帖冷却 10 分钟 |
| `match.autoReplyScore` | 0.75 | 低于则转人工 |
| 请求间隔 | 10 分钟 | 防 WAF |
| 发送失败 | 不重试 | 防重复回帖 |

**合规提醒**：每条回复带上签名 `config.reply.signature`，看起来像真人；单日总量控制在几十条以内；充值/申诉/封号一律人工。

## 11. 已知限制

1. **回复框选择器已校准** —— 已在你的账号上真发验证通过（输入框 = `[contenteditable=true]`，表情按钮 = 工具栏第 2 个，发送按钮 = text 为「发送」的 button）。
2. **WAF 封禁** —— 见第 5 节。封禁期属正常，等解封，别反复重启。
3. **排序参数要从前端 bundle 逆** —— 接口返回里**没有**排序选项（`data` 只有 `list/total/next_page`）。官方页面排序菜单「默认排序 / 回复时间 / 发布时间」对应 URL query `?sort=`，实测 `sort=created` 即按发布时间严格降序；`sort=default` 是推荐混合序，**不是时间序**。详见 skill 的 `references/api.md`。
4. **无官方「问答求助」标签** —— 那是开发者后台能力。你申请到 app 54031 权限后可切 `taptap-cli community-management list-community-moments --moment-intent 1`，识别准确率会明显提升。
5. **表情只能点选、不能打字** —— 详见 skill 的 `references/emojis.md`（含 6 个已踩的坑）。
6. **联动游戏表情不支持** —— 跨分组点选实测会插错表情。
