## 1. 一句话

抓 PVZ2 论坛新帖 → 命中答疑库就用 LLM 按上下文生成回复 → 直接打 TapTap 写接口发出去 → 读回校验 → 出四类标记报表。
**自包含**：答疑库、状态、报表全在 skill 目录内，整个目录拷给同事解压即用。

## 2. 三个进程

| 进程 | 脚本 | 干什么 | 节奏 |
|---|---|---|---|
| **守护循环** | `scripts/watch.mjs` | 论坛答疑主链路 | **每 2 分钟**检查一次，**每轮只处理队首一条** |
| **版主管理任务** | `scripts/mod-watch.mjs` | 扫加好友帖 → 回固定文案 → （移除动作默认关闭） | 2 分钟一轮，独立 opencli session |
| **手动工具** | `collect.mjs` / `reply.mjs` / `api-write.mjs` / `post-admin.mjs` / `qa-admin.mjs` / `cold-store.mjs` | 一次性任务：采集、补发、单条发、帖子诊断、答疑库管理、冷库检索 | 手动触发 |

### ⚠️ 「每轮处理几条」——最容易搞错的一点

| 场景 | 每轮处理几条 |
|---|---|
| **守护循环（`watch.mjs`）** | **1 条**（队首）。队列多长就慢慢处理多长，**没有「每轮 N 条」这概念** |
| 手动跑 `collect.mjs`（不带 `--only`） | 最多 `match.maxAutoReplyPerRun` 条（默认 8）——**这个上限只管手动单次跑** |

> 曾经有个 `config.collect.topN` 配置项，是更早「每轮批量 8 条」时代的产物，
> 随队列模式一起移除了。**代码里任何地方都不该再读它**（2026-11 已清理）。

## 3. 守护循环的两段节奏

```
① 检查（每 120s）：三个来源各按自己的节奏拉 → 挑出「需要处理」的 → 并入队列 → 按发布时间新→旧重排
② 处理（一直）：取队首 → 读评论 → 判定 → 回/夸/沉淀 → 出队 → 再取队首
```

- **三个来源**：`created`（按发布时间，新帖）/ `commented`（按回复时间，老帖又有人回）/ `notify`（回复我·@我·呼唤我）
- **不打断当前**：检查只发生在两条帖之间，正在处理的那条一定做完才轮到检查
- **队列独立文件** `data/watch-queue.json`（`state.json` 归 `collect.mjs` 独占，双写会互相覆盖 —— 历史踩过的坑）

## 4. 判定 → 动作

```
帖子 → 是不是提问？
      ├ 是 → 答疑库命中？
      │        ├ 命中（分数 ≥ 0.65）→ LLM 按三层上下文生成 → 发回复 → 读回校验
      │        │                            ├ 命中但分数不够 → 需人工
      │        │                            └ 库外 → 联网搜一次（用户认可）→ 有答案按 50% 置信度作答
      │        └ 社区已有人答 → 自动总结沉淀进库 + 夸一句（楼中楼）
      ├ 非提问但像分享/吐槽 → 轻互动（只说话，不输出信息）
      ├ 纯情绪（绝望/可惜/崩溃…）→ 陪一句（一帖一次）
      └ 玩家喊我们 → 过去互动一次（敏感问题礼貌拒绝）
```

**三层树状上下文**（`lib/thread-context.mjs`）：帖子 → 一级回复 → 楼中楼；带**父链**与 **@ 平级扩展**。

## 5. 写操作：直接打接口，不点 UI

| 动作 | 接口 |
|---|---|
| 一级回复 | `POST /webapiv2/moment-comment/v1/create` |
| 楼中楼 | `POST /webapiv2/moment-comment/v1/create-child`（参数是 `parent_id`） |
| 移除 | `POST /webapiv2/moment/v3/unlink-group`（= 解除板块关联，**不是删帖**；默认关闭） |
| 评价回复 | `POST /webapiv2/review-comment/v1/create`（**contents 是纯文本**，见 [../references/review-api.md](../references/review-api.md)） |

- **鉴权零落盘**：在已登录页面里 `fetch`，浏览器自动带 HttpOnly Cookie；不存任何凭据
- **失败自动退回点 UI**，不会整条流水线停摆
- **每次发送后读回校验**：校验不过 → 转人工，**绝不重发**

细节见 [../references/api.md](../references/api.md) 与 [../references/review-api.md](../references/review-api.md)。

## 6. 安全阀（都是「宁可少说，不可说错」）

| 阀 | 行为 |
|---|---|
| 事实来源 | **只能来自答疑库**；命中不了 → 联网搜 → 搜不到就转人工，**不编造** |
| 敏感话题 | 充值/退款/封号/申诉/投诉 → 礼貌说明帮不上，**不替官方表态** |
| 泄露自检 | 文案命中内部机制关键词 → 拒发转人工 |
| 长度 | 回复 ≤1000 字符（`clampReply` 统一裁，签名与表情保住） |
| 签名 | 默认必带，**只由脚本加一次**（模型不写） |
| 刷屏刹车 | 每帖一次 + 场景级跨帖收敛 + 玩家负反馈冷却 |

## 8. 跑起来

```bash

node scripts/doctor.mjs                   # 环境自检
```

## 9. 已知边界

- 必须有**桌面会话** + 已登录 TapTap 的 Chrome（写接口在页面里发，Cookie 由浏览器带）
- 匿名读接口高频会触发 **WAF**（200 + HTML），退避后恢复（实测 >25 分钟）→ 节奏别调太密
- 官方 CLI 需**开发者 scope**，本账号没有 → 写操作走网页版接口
- 评价区接口只做了**能力入库**，**未接入自动值守**（方案见 [方案-评价自动值守.md](方案-评价自动值守.md)）
