## 1. 总体架构

```
collect.mjs 取帖（listFeed / moment detail）
   │  post {title, summary, text, images:[{url}], intent}
   ▼
[S1] 意图门控 ── intent∈{friendCode,tiangongCode} ──→ 跳过图片识别（原流程）
   │ 其他意图
   ▼
[S2] 相关性门控 ── decorative（无关配图）──→ 跳过
   │ relevant（相关图）
   ▼
[S3/S4] 识别编排（lib/image.mjs）
   ├─ 文字/数字/说明文本/活动规则 → [S3] RapidOCR（本地免费）
   ├─ 已知植物/奖励图标/UI → [S6] 模板匹配（本地特征库，ms级）
   └─ 游戏画面/开放语义 → [S4] VLM（跟随DSH/他人key）
   │  imageText（结构化识别结果）
   ▼
[S5] 回灌 post.text / post.imageText
   ├─ QA 匹配查询词（qa-vector + 关键词）
   ├─ 网络搜索查询词 q（lib/websearch.mjs，已有）
   └─ LLM 组答上下文（compose-reply.mjs，已有）
```

**新增模块**：`lib/image.mjs`（取图+下载+识别编排）、`lib/vision.mjs`（多模态 LLM）、`lib/ocr.mjs`（RapidOCR 桥接）、`scripts/ocr_server.py`（RapidOCR 微服务）、`assets/game-features/`（模板库）。
**改动模块**：`http.mjs`（extractImages）、`collect.mjs`（门控+回灌）、`llm.mjs`（多模态扩展）、`compose-reply.mjs`（上下文）、`config.json`（image 段）。

## 2. S1 取图 + 意图门控

### 2.1 取图 `extractImages`（`lib/http.mjs`）【已实测确认 2026-11-16，见 evidence/06】
- **图片位置（实测）**：在 **`moment.topic.footer_images[]`**，**不在 contents.json**（topic 帖 type=2 无 contents.json，正文在 `topic.title/summary`）。
- **feed 层即带图（实测）**：`feed/v7/by-group` 的 list item 已含 `topic.footer_images` → **取图无需额外 detail 请求**。
- **完整 schema（实测）**：
  ```json
  { "url":".../_tap_ugc.jpg", "medium_url":"..._m.jpg", "small_url":"..._s.jpg",
    "large_url":".../_tap_ugc.jpg",
    "original_url":"https://img2-tc.tapimg.com/moment/etag/<hash>_<ts>.jpg",
    "original_format":"jpeg", "width":2400, "height":1080,
    "color":"0x8e8a67", "original_size":1601663 }
  ```
- 新增 `extractImages(item)`：读 `item.moment.topic.footer_images[]` → `post.images=[{url:original_url, width, height, format, size}]`（OCR/VLM 用原图 `original_url`）。
- **取图通道（实测修正）**：匿名 + **`X-UA` 头**即可读 feed/detail（之前 `success=false` 是漏 X-UA，**非 WAF、非必须登录态**）。skill `ttGet` 已带 X-UA（`http.mjs` L9/L134），直接复用。moment id 用 **`id_str`**。
- **CDN 下载（实测）**：`img2-tc.tapimg.com` **无防盗链**——裸 GET（无 Referer/UA）也返回 200 JPEG。直接 GET `original_url` 落地临时文件供 OCR/VLM。
- **端到端已验证**：取「一发出了紫手套」帖（id_str=871396454843813708）→ 下载原图 → 可读，内容为**活动页面**（获得奖励弹窗：紫手套碎片×15/钻石×334；狂欢嘉年华活动/剩余1天9时/可能获得的植物碎片）——正是重点①活动页面，VLM 可语义读懂。证据：[evidence/06-图片取图schema实测-20261116.md](../evidence/06-图片取图schema实测-20261116.md) + 样本图。
- **结论**：S1 大幅简化——无需登录态、无需额外 detail、无防盗链处理，工作量下调。

### 2.2 意图门控（规则1）
- `collect.mjs` 已有意图分类（question/code/praise/…）。**码意图（friendCode/tiangongCode）→ 直接跳过图片识别**，走原固定提醒+移出/撮合流程。
- 配置：`config.image.skipIntents = ['friendCode','tiangongCode']`（可扩展）。
- 验收：码意图帖 100% 不触发 OCR/VLM。

## 3. S2 相关性门控（规则2，控费关键）

- 目标：区分**无关配图**（装饰/表情/无关晒图）与**相关图片**（与问题/帖子主题相关）。
- 两级判定：
  1. **启发式先行**（免费）：正文已长且明确 → 图多为配图；正文短 + 求助意图 + 带图 → 多为相关；纯表情/头像类 → 无关。
  2. **轻量 VLM 二分类兜底**（极低成本）：prompt「这张图与帖子问题相关吗？只答 相关/无关」，仅对启发式判不明的图调用。
- 输出：`post.imageRelevance = 'relevant' | 'decorative' | 'unknown'`；**只有 relevant 进 S3/S4**。
- 配置：`config.image.relevanceGate = { mode:'heuristic+vlm', vlmMaxPerRun: N }`。
- 起步（已定）：**纯启发式**跑通；VLM 二分类按需后开。

## 4. S3 本地 OCR（RapidOCR）

- **引擎**：RapidOCR（`pip install rapidocr`；本机 onnxruntime 1.19.2 / opencv 4.5.4 / Pillow 已在，装即用，免费离线）。
- **桥接** `lib/ocr.mjs`：Node 调 Python。两种方式（S3 选型）：
  - A. spawn Python 子进程（注意沙盒/stdio 边界，见 script-execution-pitfalls；`stdio:'inherit'` 或文件交换避免 EPERM）。
  - B. **RapidOCR 本地 HTTP 微服务**（`scripts/ocr_server.py`，FastAPI/内置 http）→ Node fetch 调用（推荐：解耦、可复用、避免子进程 stdio 坑）。
- **预处理**（opencv）：ROI 裁剪 → 灰度 → 自适应二值化 → 去噪，提升游戏艺术字/低对比度准确率。
- **适用**：错误弹窗文案、关卡/阳光数字、**活动规则文本**、**植物图鉴说明文本**、奖励名称文字。
- 输出：`{ text, boxes:[{text,rect,conf}] }`。
- 验收：真实错误文案/图鉴说明文本识别准确率跑样本 ≥ 目标（S3 实测）。

## 5. S4 VLM 理解（跟随 DSH + 他人 key）★核心

### 5.1 通道解析（完全沿用 `llm.mjs` 现有顺序）
`llm.mjs` 顶部注释正是此原则（「复用 DSH 配置 + 让别人能提供 API Key」）。新增 `lib/vision.mjs` 复用同一解析：
1. **`config.llm.vision`（apiKey/baseURL/model 三项齐全）→ 直接用** —— **给别人用**的路子（他人提供自己的 VLM key）。
2. **否则读 DSH 路由**：`~/.dsh/profiles/web/cordis.patch.yml` providers + `~/.dsh/.credentials.yaml` refs，按 chain 顺序选 **vision-capable 模型** —— **跟随 DSH / 给自己用**。
3. **都没有 → 返回 null**，调用方降级（agent-in-loop 标记 / 跳过），绝不瞎编。

### 5.2 多模态扩展（`llm.mjs`）
- 现有 `chat()` 只发文本。扩展支持 image content blocks：
  - **openai-completions** 风格：`content:[{type:'text',text},{type:'image_url',image_url:{url}}]`（url 可为 CDN URL 或 base64 data URI）。
  - **anthropic-messages** 风格：`content:[{type:'image',source:{type:'base64',media_type,data}},{type:'text',text}]`。
- **模型选择**：vision 通道需 vision-capable 模型（如 qwen-vl 系列）。`config.llm.vision.model` 显式指定优先；跟随 DSH 时从 chain 里挑支持视觉的模型（providers.models 标注或配置 `visionModels` 白名单）。
- **凭证铁律**（沿用 llm.mjs）：只在内存用，**不落盘、不打印、不进日志**。

### 5.3 识别 prompt（结构化输出）
约束 VLM 输出 JSON：`{ scene:'错误弹窗|关卡|阵容|活动页面|植物图鉴|其他', plants:[...], rewards:[...], errorText:'', stage:'', description:'', userIntent:'' }`。
- **活动页面**：活动植物、奖励物品、参与条件/进度、规则要点。
- **植物图鉴**：植物名称、属性数值、技能/说明文本摘要。
- 结果文本化后并入 `post.imageText`。

### 5.4 降级与控费
- 无 vision 通道 → 标记高价值图入「待看图」队列（agent-in-loop 兜底）或跳过。
- 控费：S2 门控 + 单轮 VLM 配额 + 识别缓存（见 S5）。

## 6. S5 回灌流水线（规则3）

- **并入**：`post.imageText`（独立字段，标来源 OCR/VLM/模板）；`post.text` 追加 imageText 摘要。
- **三处自动受益**（现有钩子，改动小）：
  | 现有 | 位置 | 接入 |
  |---|---|---|
  | QA 匹配 | `qa-vector.mjs` + 关键词 | 查询文本含 imageText |
  | 网络搜索 | `lib/websearch.mjs`（单轮≤2次、同帖24h不重搜） | `q = 正文 + imageText` |
  | LLM 组答 | `compose-reply.mjs`（topicForMatch/三层上下文） | 上下文含 imageText，LLM 看得到图里信息 |
- **置信度**：VLM/OCR 识别内容属二手信息，沿用现有 webNote 的 50% 置信度话术策略（开口「小鲸鱼看到图里大概是…」，结尾以玩家实测为准）。
- **缓存**：按图 URL/hash 缓存识别结果到 `data/image-cache.json`（TTL 可配），避免重复识别省钱。

## 7. S6 游戏特征模板库（本地 skill，概要）

- **位置**：`assets/game-features/`——模板图（PNG）+ `features.json`。
- **特征定义 schema**：
  ```json
  { "id":"peashooter", "name":"豌豆射手", "category":"plant",
    "method":"template", "template":"plants/peashooter.png",
    "roi":[x,y,w,h], "threshold":0.85, "aliases":["豌豆"] }
  ```
  method ∈ `template`（模板匹配）/ `ocr`（数字/文字 ROI）/ `color`（品质边框找色）。
- **内容**：植物图标、**活动奖励图标**、**图鉴植物**、UI 按钮、品质边框、阳光/关卡数字 ROI、常见错误弹窗模板。
- **引擎**：opencv 模板匹配（多尺度 + NMS，相似度阈值），ms 级免费；参考 BetterGenshinImpact `RecognitionObject`。
- **与 VLM 配合**：模板命中 → 结构化特征（快/准/免费）；未命中 → VLM 兜底。
- **维护**：游戏版本更新换 UI/新植物 → 补模板（记入 `references/ops.md`）。
- **优先级（已定）**：按 S1→S6 顺序，**S1–S5 完成立即接 S6**（不后置）。

## 10. 隐私 / 安全 / 控费

- **隐私**：玩家截图可能含账号/个人信息 → 敏感信息脱敏；隐私敏感场景优先本地 OCR/模板，云端 VLM 调用前确认合规。
- **凭证**：vision key 只在内存用，不落盘/不打印/不进日志（沿用 llm.mjs）。
- **控费**：S2 门控 + 单轮 VLM/OCR 配额 + 识别缓存 + 码意图跳过。
- **WAF**：取图走页面上下文（登录态），不密集匿名探测（匿名 feed 已实测不可靠）。

## 11. 验收标准

1. 码意图帖 100% 跳过图片识别。
2. 无关配图按门控跳过；相关图识别内容正确并入 `post.imageText`/`post.text`。
3. 带图求助帖（含活动页/图鉴）：QA 命中率 / 联网搜到率 / 答疑质量较纯文本有提升（跑样本对比）。
4. VLM 通道：`config.llm.vision` 三项齐全 → 用他人 key；为空 → 跟随 DSH；都无 → 降级不瞎编。
5. 凭证不进日志/报表；识别缓存命中不重复计费。
6. 新增 3 套离线测试全绿；现有 28 套不回归。
