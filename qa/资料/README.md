# 资料库（qa/资料/）

> **这不是答疑库。** 答疑库存的是「玩家问 X → 我们答 Y」的答案；
> 资料库存的是**游戏机制、流程、活动规则**这些事实基础。回答玩家时可以拿它当参考，但它本身不是答案。
>
> **程序可读**：每个文件都有 frontmatter，`lib/qa-materials.mjs` 按 keywords 匹配、按 `##` 分节取用。

---

## 为什么一版块 / 一活动一份文档

多人同时维护时，**不同人改不同文件 → git 零冲突**。这和答疑库「一条一文件」是同一个道理。

- 一个人补「无尽模式」，另一个人补「万圣节活动」→ 两个文件，互不影响
- 只有两人同时改**同一个版块**才会冲突，冲突范围也只是一份文档

## 文件命名

| 类型 | 命名 | 例子 |
|---|---|---|
| **玩法 / 系统版块** | `doc-<系统>.md` | `doc-endless.md`（无尽）· `doc-chase.md`（追击）· `doc-duel-mode.md`（双人对决） |
| **商店 / 抽卡系统** | `doc-<系统>.md` | `doc-panini-treasure.md`（潘妮秘宝） |
| **活动 / 赛季** | `doc-event-<活动>.md` | `doc-event-halloween.md` · `doc-duel-rewards.md`（赛季奖励） |
| **流程指引** | `doc-<场景>.md` | `doc-account-recovery.md`（账号找回） |
| **术语表** | `doc-glossary*.md` | `doc-glossary-plants.md`（植物缩写）· `doc-glossary-phrases.md`（操作口诀） |

**活动类必须带时间范围**：在 frontmatter 写 `scope:`，否则下个赛季的人不知道这数据是哪期的。

## 文件格式

```markdown
---
id: doc-endless                 # 必填，唯一，与文件名一致
title: 无尽模式                  # 必填，人看
type: mechanism                 # 必填：mechanism | process | event | glossary
keywords: [无尽, 无尽模式, 无尽怎么打]   # 必填，程序按这个匹配
tags: [玩法]                     # 可选，分类
scope: 6.2 版本赛季              # 活动/赛季必填，说明数据是哪期
updated: 2026-11-26             # 必填
confidence: 95                  # 可选：95=官方/人工确认 / 50=社区说法
source: https://…               # 可选：出处链接
---

## 一句话结论          ← 每个 ## 节都要能独立看懂

正文。程序会按问法挑最相关的节，所以**每节要自洽**，别跨节指代「上面说的那个」。

## 另一条规则

正文。
```

### 四条硬规矩

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | **`##` 分节，每节自洽** | 程序按节取用，跨节指代会读不懂 |
| 2 | **数字/名称/机制写准** | 这是事实基础，错了答案就错 |
| 3 | **历史数据不改，另开新文件** | 赛季/版本变了就新建 `doc-event-<新赛季>.md`，旧的留作历史 |
| 4 | **keywords 必须写玩家的口语变体** | 匹配是**按整词命中**打分的，只写书面词就召不回来 |

> 第 4 条最容易漏。2026-11-26 实测：`doc-account-recovery` 只写了「号没了」，
> 玩家说「我**号丢了**能找回吗」→ 一个字都不命中 → 资料没被引用。
>
> 一条经验：**同一个意思，把玩家可能说的几种说法都列上** ——
> 书面词（丢失 / 恢复）+ 口语（丢了 / 没了 / 不见了）+ 场景（换手机 / 重装）。
> 但**别放太泛的词**（光一个「丢」「清空」），容易误命中，把不相关资料塞给模型。

## 多人怎么协作

| 场景 | 做法 |
|---|---|
| 我要补一个新的游戏版块 | 新建 `doc-<版块>.md`（别人不会碰这个文件） |
| 我要补某个活动的规则 | 新建 `doc-event-<活动>.md` |
| 我要改已有版块的内容 | 改那份文档 —— **只有碰同一份才会冲突** |
| 赛季/版本更新了 | **新建** `doc-event-<新赛季>.md`，旧文件不动 |

> 结论：**先按版块/活动拆文件，再动手写**。别把多个版块塞进一份文档 —— 那等于把所有人都往同一个文件里赶。

## 和答疑库的关系

```
玩家提问
   ↓
① 答疑库（qa/entries/）匹配 → 有答案就照答案答
   ↓ 没命中
② 资料库（qa/资料/）匹配 → 拿事实当参考，让 LLM 自己组织话
   ↓ 都没
③ 联网搜 / 转人工
```

资料库的存在是为了**减少「这个该写进答疑库还是写进资料」的纠结**：
机制、流程、规则类 → 资料库；具体问答 → 答疑库。

同一件事两边都有也行 —— 答疑库写短的答法，资料库写完整机制。
